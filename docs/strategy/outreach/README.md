## 必須ブロック

### 1. 前提整理

必ず書く:

- **誰向けか**（相手側 / 自分側）
- **いま何が起きているか**（課題を相手の言葉で）
- **なぜ今・なぜこの地域か**
- **この資料で約束しないこと**（未確定加盟・未確定KPI・即時本番など）

#### 共感パートのレビュー（厳守・O9）

「いま起きていること」「なぜこの話か」など **共感が主目的の見出し**は、一般論・当たり前で進めない。

| 合格 | 不合格 |
|------|--------|
| 固有名・場所・事業名・事例が1つ以上 | 「候補は多いが見えない」だけ |
| 数字があり、出典 or `UNKNOWN／未取得` 明示 | 政策スローガン・業界あるあるの復唱だけ |
| 「だから相手の席で問題になる」まで1行で結ぶ | 固有名も数字もなく次へ |

レビューラベル（段落ごと・残ったら送付不可）:

- `NG一般論` — 誰の席でも言えることだけ
- `要出典` — 数字・固有名があるが出典なし
- `FACT不足` — 共感の核が OPEN/推測のまま断定口調
- `OK具体` — 例＋数字（または UNKNOWN 明示）で共感が立つ

### 2. プロダクト説明

知らなくてよい前提で、層ごとに役割を書く:

| 層の例 | 役割 | 誰が使うか |
|--------|------|------------|
| 調査・更新（LocalManus等） | 情報の調査・更新 | 運用・地域側 |
| 発見・信頼（Portal） | 見せる・探索と確定を分ける | 来訪者＋関係者 |
| 決済・証跡（SuzuPay） | 支払い・インセンティブ | 来訪者＋店舗 |

加えて **体験の一本道**（推奨 → 参加 → 決済）を短く。来訪者面に補助金・社内用語を載せない。

### 3. ビジョン説明

うまくいったときの姿を **定性で**書く（未来の1段落で可）。

- 「1枚で説明できる」「未確認を対外に出さない」「見える化の先に決済がある」など
- 未確定の数字・加盟店名・採択確約は書かない

### 4. 着地（必須・弱いまま出さない）

「ヒアリングしたい」だけでは着地にならない。次を表で書く:

| トラック | 持ち込み先 | 置くもの | 着地の形（終わり方） | 成功の定義 |
|----------|------------|----------|----------------------|------------|
| 主着地 | （組織は送付前にFACT化） | 打診1枚＋デモ等 | 例: 協議席・次窓口 | 具体的な次アクション1つ |
| 並行（政策・補助など） | 出典URL付き | 全体構想の種 | 接続相談（採択は約束しない） | 器に載る／次公募の準備 |
| 並行（決済側など） | 別席と明記 | 役割分担1枚 | 接続条件の整理 | 次アクション1つ |

大阪打診の型（参照）:

- **A** 観光局・DMO＝表の席（主）
- **D** 観光庁OT／面的受入事業＝政策の器（並行・採択約束しない）
- **E** SuzuPay側＝決済レール（並行・別トラック）

会話順の既定: **まず主着地**。並行は一言＋裏で進める。
