## 0. 前提整理（なぜこの話か）

### 誰の話か

- **あなた側:** 大阪の観光・地域の関係者（政策・実務・現場をつなぐ立場）
- **私たち側:** 地域の発見 → 回遊 → 参加 → 決済をつなぐ仕組みを作っているチーム（決済レール名が SuzuPay）

### いま起きていること

<!-- レビュー: 旧稿は NG一般論（「見えない／バラバラ／信頼」だけ）。具体例＋出典付き数字に差し替え -->

共感してほしいのはスローガンではなく、**すでに数字と失敗が出ている現場**と、**国が面で金を付けている枠**がある、という事実。

1. **人が動く設計は実証されている（宮島・廿日市）**  
   デジタルマップ＋スタンプラリー＋駐車場混雑LEDで、混雑を「来るな」ではなく非混雑へ誘導。  
   **16日間で 1,147 人参加**。写真撮影要素を使った参加者は、使わなかった参加者より滞在時間・スタンプ取得が約 **3倍**（観光庁事例集／`overtourism-cases.md`）。  
   → 「見える化だけでは動かない。誘導の設計が要る」は一般論ではなく、この実績から言える。

2. **看板・誘導員だけでは足りない失敗も公開されている（鎌倉）**  
   鎌倉高校前踏切のスポット外撮影者を **30%減**が目標 → 実際は **12.6%増**（同事例集）。  
   → 情報を出すだけでは逆効果もありうる。地図・推奨・参加・決済まで一本化する理由。

3. **政策側は「点」から「面」の補助に移っている（FACT）**  
   観光庁「オーバーツーリズムの未然防止・抑制をはじめとする観光地の面的受入環境整備促進事業（令和8年度当初予算）」。  
   地域一体型は補助率 **2/3・上限 2億円**（[事業ページ](https://www.mlit.go.jp/kankocho/seisaku_seido/kihonkeikaku/jizoku_kankochi/jizokukano_taisei/overtourism/jigyo.html) / [特設](https://ot-kankoseibi.go.jp/)）。一次・二次採択は公表済 → **今の採択確約はしない**が、器としての接続は現実の議題。

4. **大阪固有の混雑KPI（UNKNOWN）**  
   大阪の通り別・時間帯別の公式混雑数字は本草案では未取得。送付前に府・市・DMO公表値を1つ入れる（担当: 要取得）。空欄のまま一般論で埋めない。

### なぜ大阪か

型の横展開が前提のプロダクトである。大阪を **最初のショーケース面（パイロット面）** として相談したい。  
全国の裏方サーチは存在するが、対外説明の主役にはしない。

## 1. ビジョン（目指す姿）

> 大阪の関係者が、公共・緑化・循環・受入の候補を **地図と表で共有**できる。  
> 探索中と確定が色で分かれ、**確定情報だけが対外に出る**。  
> 決済の入口は SuzuPay。ポータルは発見と信頼の器、SuzuPay は決済と証跡のレール。  
> 加盟店名は人手確認前に載せない。表に出すのはパイロット面（まず大阪）である。

成功のイメージ（定性）:

- 「大阪でこう見える」が **1枚で説明できる**  
- 未確認情報を対外に出さない運用が **最初から設計されている**  
- 見える化の先に、決済レールまでの **一本の物語**がある  
- 打診の結果、次の協議・データ・窓口のアクションが **1つ**取れる

## 2. プロダクト説明 — どう一本につながるのか

知らなくてよい前提で書く。部品のカタログではなく、**前提の課題に対する一本の鎖**として読む。

### つながりの要約（先に結論）

| 前提で共有したこと | プロダクト側の答え | 大阪で見せるもの |
|--------------------|--------------------|------------------|
| 見える化だけでは人は動かない（宮島の誘導実績／鎌倉の失敗） | Portalで「別の時間・場所」を推奨し、参加まで設計する | 地図上の推奨→小さな参加 |
| 未確認情報で信頼が壊れる | scouted（探索）と registered（確定）を色分け。対外は確定のみ | 凡例付き大阪面 |
| 決済が資料と分断されるとパイロットが終わる | 推奨先の支払い入口が SuzuPay（発見の直後にレール） | Portal帯の隣に決済帯 |
| 「面」で動かす政策がある（観光庁OT・面的受入） | 戦略5軸で面を切る。全国サーチは裏方 | 戦略1本をデモで深掘り |
| 型の横展開が前提 | 同型ポータルは既にある。大阪は最初のショーケース面 | 打診後デモ＝A着地の席 |

一文で言うと: **Portalが「どこへ行くか」を信頼できる形で示し、SuzuPayが「そこで払う」を受け、来訪者体験がその上を一本で歩き、既存資産が「もう型はある」証拠になる。**

### 三層（役割分担）

| 層 | 名前 | この鎖の中での役割 | 主な利用者 |
|----|------|-------------------|------------|
| 調査・更新 | LocalManus（地域AI） | 戦略軸に沿って候補を集め、Portalに渡す裏方 | 運用・地域側 |
| 発見・信頼 | Tourism Portal / Portal Factory | 候補を地図と表にし、探索と確定を分けて見せる | 来訪者＋関係者共有 |
| 決済・証跡 | SuzuPay | Portalで選んだ先での支払い・インセンティブ | 来訪者＋店舗 |

来訪者面には補助金や社内用語を出さない。補助金・採択の話は着地Dのトラック。

### Portal（発見と信頼の器）— 鎖の「見る・選ぶ」

前提「見えない」「未確認で壊れる」への直接の答え。

1. 公共・緑化・循環などの候補を、**戦略別**に地図と表で整理する  
2. **探索中（scouted）** と **確定（registered）** を色分けし、確定だけを対外に出す  
3. 自動反映は探索中まで。確定は人手確認後のみ  

戦略の切り口（サーチ軸・定義済）は、地図を「なんとなくのピン」にしないためのもの:

- 花き・緑化 / 剪定バイオマス / 建設副産物 / 堆肥 / 公共調達循環  

ここが次の「来訪者体験」の入力になる。**戦略で切った候補 → 推奨される時間・場所**が、体験の出発点。

### 来訪者側で起きてほしいこと — 鎖の「歩く」

Portalの出力を、来訪者の行動に変換する段。宮島型（誘導で動かす）を大阪面に載せるイメージ。

**推奨（別の時間・場所・体験）→ 小さな参加 → 現地決済** の一本道。

- 「混雑だから来るな」ではなく、**まだ余白のある時間と場所を先に出す**（前提の共感パートと同じ思想）  
- 「小さな参加」はスタンプ・クエスト等の設計枠（具体の大阪施策名は未確定＝空欄可）  
- この動線の**終点**が次の SuzuPay

Portalだけだと「良い地図」。体験まで設計して初めて「動かす装置」。

### SuzuPay（決済と証跡のレール）— 鎖の「払う・残す」

前提「決済がバラバラでパイロットが資料で終わる」への答え。**Portalで見つけた先に直結する支払い入口**であり、単体の決済Pitchではない。

- 説明は常に Portal（発見・信頼）と**セット**  
- 大阪での加盟・稼働の確定状況は、**現時点では未確定（空欄が正しい）**  
- 加盟の実務は着地E（SuzuPay側別席）で並行。対外Aの席では「レールの位置づけ」まで  

### すでに持っているもの — 鎖の「もう型はある」

内側FACT。ビジョンの「既に動く型」を裏づける。

| 持っているもの | 鎖のどこを証明するか | 打診での使い方 |
|----------------|----------------------|----------------|
| 同型の説明用ポータル面（価値探索／インバウンド）と説明文書 | Portal層が既に存在する | 「型の実物」として言及（全国opsは出さない） |
| 戦略軸に沿った調査の裏方 | LocalManus／サーチが候補を供給できる | デモでは一言。主役にしない |
| 大阪ショーケース面（整備中） | A着地で見せる「大阪1枚」 | 打診後デモでお見せする想定 |

つまり: **既存面＝型の証拠、大阪面＝今回の着地Aのデモ道具、裏方サーチ＝燃料（表に出さない）。**

### この節の読み方（再掲）

課題（動かない・見えない・決済切断・信頼）  
→ Portal（戦略地図＋探索/確定）  
→ 来訪者動線（推奨→参加→決済）  
→ SuzuPay（見つけた先の支払い）  
→ 既存資産＋大阪面（型の証拠とデモ）  
→ 着地Aで見せ、Dで政策の器に載せ、Eで決済接続を並行する。

## 着地のイメージ（どこに何を持っていくか）

この打診は **1つの相手に1つのお願い**ではなく、次の3トラックを意識して進める。主役は A。D と E は並行。

### A. 観光局・DMO（主着地）— 「大阪で見せる席」

| 項目 | 内容 |
|------|------|
| 持ち込み先 | 大阪の観光ご担当（局・DMO等。**正式名称は送付前にFACT化**） |
| 置くもの | 本打診1枚 ＋（整備後）大阪ショーケースデモ |
| 着地の形 | 30–45分ヒアリング → パイロット面としての位置づけ協議 → 次窓口1つ |
| 成功 | 「大阪でこう見える」を一緒に見る約束が取れる |

### D. 観光庁オーバーツーリズム関連事業（政策・補助の器）— 並行

出典（FACT）: 観光庁「オーバーツーリズムの未然防止・抑制をはじめとする観光地の面的受入環境整備促進事業（令和8年度当初予算事業）」  
https://www.mlit.go.jp/kankocho/seisaku_seido/kihonkeikaku/jizoku_kankochi/jizokukano_taisei/overtourism/jigyo.html  
特設: https://ot-kankoseibi.go.jp/

| 項目 | 内容 |
|------|------|
| 持ち込み先 | 地域一体の申請主体（自治体・DMO等）＋我々は型・面・決済レールの提案側 |
| 置くもの | 全体構想の種 ＋ 本打診（Portal＝面的な発見/誘導、SuzuPay＝域内決済） |
| 着地の形 | 「面的受入・需要分散・行動変容」の器に、見える化ポータル＋決済を載せる相談 |
| 注意 | 令和8当初の一次・二次採択は既に公表済み。**今すぐ採択を約束しない**。次期・関連枠・地域側への型提供として接続する（PLANNED） |
| 成功 | 補助・政策の文脈で「事業の部品」として名前が載る／次公募の準備席に座れる |

我々の型との対応（断定しすぎない）:

- 混雑の「来るな」ではなく **別時間・別場所へ動かす**（宮島型などの事例型）  
- 関係者共有の地図（探索／確定の分離）＝面的対策の見える化  
- 推奨先での決済＝域内消費の受け皿（SuzuPay）  

### E. SuzuPay側（決済レール）— 並行・別トラック

| 項目 | 内容 |
|------|------|
| 持ち込み先 | SuzuPay / 決済展開の大阪窓口（観光局打診とは別席） |
| 置くもの | Portal＝発見と信頼、SuzuPay＝決済と証跡、の役割分担1枚 |
| 着地の形 | 大阪パイロット面でのレール接続条件の整理（加盟・稼働は空欄のまま相談） |
| 成功 | 観光側デモと矛盾しない決済側の次アクションが1つ決まる |

### 3トラックの関係（1図で）

```
A 観光局・DMO ── デモとパイロットの「表の席」
D 観光庁OT事業 ── 政策・補助の「器」（並行・採択は約束しない）
E SuzuPay側   ── 決済レールの「裏の席」（並行・加盟は空欄）
        └── 交点: 大阪パイロット面
```

送付・会話の順序の推奨: **まず A**（表）。D は「政策の器として接続可能」と一言。E は社内／決済側で並行。


## 4. 大阪でお願いしたいこと（Ask）

**主（A 観光局・DMO）**

D. 観光庁「面的受入環境整備／オーバーツーリズム未然防止・抑制」事業など、政策・補助の器への接続可能性（採択は約束しない）
